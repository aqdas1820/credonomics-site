# Security Policy

## Reporting a vulnerability

Please do **not** report security vulnerabilities through public GitHub issues, discussions, pull requests, screenshots, or social media.

Report suspected vulnerabilities privately to **support@credonomics.in**. For company or partnership matters that are not security reports, use **founder@credonomics.in**.

Include only the information needed to reproduce and understand the issue:

- affected page, route, feature, or commit
- impact and realistic attack scenario
- minimal reproduction steps
- browser / operating system when relevant
- any non-sensitive logs or screenshots

Do not include passwords, API keys, session cookies, customer data, bank details, payment credentials, private documents, or other secrets.

## Safe testing expectations

- Use synthetic or test data wherever possible.
- Do not test against real customer accounts or real financial transactions.
- Do not attempt denial-of-service, destructive data modification, social engineering, credential theft, or access to data that is not yours.
- Stop testing if you unexpectedly encounter private or sensitive information.
- Do not publish exploit details before CredoNomics Investment Solutions has had a reasonable opportunity to investigate and remediate the issue.

## Scope and status

This repository contains the public CredoNomics web application and related tooling. Some financial, billing, authentication, or experimental paths may be disabled, private, staged, or not approved for production use. The presence of source code does not imply that a feature is enabled or financially active.

We will acknowledge good-faith reports and assess them based on reproducibility, impact, affected deployment state, and available evidence.
