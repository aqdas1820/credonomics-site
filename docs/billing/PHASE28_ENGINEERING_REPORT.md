## Confirmed findings and changes

| Finding | Development change / acceptance boundary |
| --- | --- |
| Stateless links lacked revocation, persistent rate limits and an issuance lock | Added service-only durable reservation/completion/access/revoke RPC design with private RLS-enabled storage and append-only audit events. Missing functions or missing `YOUPI_LINK_LEDGER_APPROVED=true` fail closed. SQL was executed only in a newly initialized disposable local PostgreSQL cluster. |
| Concurrent issuance could create duplicate gateway sessions; gateway retry can rewrite terminal order IDs | Reserve the invoice before outbound creation; concurrent pending attempts deny. Reuse the saved payment ID and original issued timestamp, authenticate its current owner/state, persist the link digest before returning the URL. Pending/ambiguous timeouts, expiry, revocation and merchant changes require operator reconciliation; no automatic retry/new session. |
| Public gateway status did not identify merchant | Require server-only `YOUPI_MERCHANT_KEY` and authenticated status with exact merchant/payment/order/INR rupee and paise matches, payable statuses only. Companion upstream adds merchant ID exclusively to owner-authenticated status. Unpatched upstream denies link issuance. |
| Invoice references/canonical values and response size needed stricter validation | Canonicalize invoice and configured merchant IDs; validate invoice numbers before contacting gateway; return only explicitly selected invoice fields; bound streamed JSON bytes and cancel oversized responses. Signing rejects timestamp overflow. |
| Terminal/changed invoices and status failures must never remain payable | Check live immutable invoice eligibility before handoff and again inside ledger functions; require current gateway INITIATED/ACTIVE/QUEUED with exact amount and merchant. PROCESSING/terminal/error states deny. Unpaid/zero bank evidence is mandatory. |
| Link replay could continue after revocation | Match only registered token SHA-256 digest, check expiry/revocation and live invoice on every view, limit views to 30 per link/calendar minute. Links remain bearer URLs and intentionally permit bounded repeat views, not one-time identity proofs. Unregistered old PR #9 tokens deny. |
| Issuance abuse lacked a durable budget | At most 10 eligible requests per authenticated actor over a rolling minute, across processes. Rate-limit responses are HTTP 429 with Retry-After. Access and issuance audit records contain invoice/payment/merchant references, no raw token, customer name, email, phone or secret. Denied public forged signatures never trigger database/gateway lookup. |
| CSRF, redirects and privacy boundaries | Preserve server-verified admin allowlist/app_metadata checks; enforce canonical same-origin and Fetch Metadata on POST. Every gateway fetch refuses redirects. Private payment URLs receive no-store/no-referrer/noindex and CSP frame/form restrictions; disabled URLs get middleware HTTP 404 before Auth work. Public URLs never refresh unrelated Auth cookies. |
| Hostnames could resolve to private/link-local addresses | Reject private/reserved IPv4 and non-global IPv6 DNS answers before default gateway requests; validate API and checkout DNS. Exact HTTPS origins are configured server-side, never supplied by customers. **DNS preflight is not connection pinning: rebinding-safe network egress and approved hosts remain a release blocker.** |
| New UUID order format did not match older webhook observation adapter | Added service-only ledger-bound UUID-order adapter requiring saved invoice/merchant/payment/amount, then records in existing immutable observation ledger. Existing invoice-number integrations retain their path. |
| Webhook method was ignored | Require recognized payment method; COD remains order placement and cannot enter the bank-observation adapter. Only UPI observations reach that adapter. A raw-body-valid SUCCESS never changes financial status or issues a receipt. |
| Upstream webhook omitted UTR | Companion patch includes bank reference only from an observation bound to this payment and exact amount, otherwise null. No invented reference for COD/counter payments. Raw-body MAC behavior is preserved. |
| Unsupported desktop/mobile trust and social-proof claims | Companion patch removes unsupported business badges/order counts/protection fallback text, disables promotional slots in CSS before JavaScript, and ignores merchant overrides for those slots. No claim of business verification was added. |

The new SQL does **not** mutate invoices, bank-credit evidence or receipts. It uses the existing private-schema/RPC permission model with explicit service-role execution grants, empty application search paths, and role checks. Hosted Supabase/PostgREST acceptance and production Auth are not inferred from local tests.
